## 1. 研究问题与贡献

长程操作要求机器人根据过去事件识别目标、保持顺序和计数，并连续执行动作。高层视觉语言模型（VLM）能分解任务、解释观察和处理新情况，视觉语言动作模型（VLA）则根据具体子目标生成连续动作。两者的推理速度和适用范围不同。MAEX 在所有模型权重冻结的条件下研究两个问题。

1. **高层规划怎样跟上执行？** 在每个子任务完成后才规划会增加边界等待。提前规划可以利用执行时间，但单一预测路径很难覆盖失败或证据不足的结果，返回的计划也可能依赖已经变化的场景。
2. **物理结果怎样可靠地改变任务状态和后继行为？** 长程任务中，同一帧可能支持不同的对象身份或进度解释。一次工具回执、重复的观察描述或候选计划中的预期效果，都不足以证明任务已完成；任务目标达成也可能早于下一控制器的接管就绪。

**核心思路是提前准备条件后继，在状态与执行条件得到核查后逐步使它们生效。** EpiKnow 已有冻结 VLA、异步过程观察、episode 历史和跨 episode 经验巩固。MAEX 复用这些能力，改变历史经验被复用的形式，以及候选计划取得执行权的方式。 [EpiKnow 原稿](EpiKnow.pdf)

| 拟验证的贡献 | 机制 | 需要建立的证据 |
| --- | --- | --- |
| **可复用的条件控制结构** | 将经验组织成包含适用条件、动作、验证和恢复的子树。Planner 在当前任务约束下实例化并扩展意图树，未决分支反向提出观测需求。 | 用同一来源经验比较文本检索与子树实例化，测量实际所需后继的覆盖、规划开销与任务成功。 |
| **围绕同一棵树的异步准备与提交** | Executive 分开接纳事实和授权意图，依据当前进度与分支依赖接续晚返回的子树，并在可核查的边界交接。 | 在计划结构、模型和工具相同时比较串行、简单异步与完整协议，测量边界等待、接续有效性与错误提交。 |

三类记忆、选择执行器和原地恢复支撑这两项贡献。单 VLA 也能运行该架构。类脑机制提供组织动机，性能主张由两项机制的闭环对照支持。

- **Memory as reusable control structure.** The planner instantiates procedural subtrees under the object bindings and progress constraints of the current episode.
- **Asynchronous planning and verified handoff.** The executive prepares continuations during execution, incorporates compatible parts of delayed plans, and grants control when the required evidence and handoff conditions are satisfied.

## 2. 总体架构、记忆与类脑动机

### 2.1 总体架构

给定任务指令及可用示范，Planner（高层 VLM）生成全局子目标与顺序约束，在活动子任务附近扩展有限的条件分支。**Intention Tree**（意图树）保存已走过的路径、当前意图与待核查的后继。**Executive**（执行中枢）用观察结果更新任务状态，解释树中的条件，决定继续、补证、恢复或交接。**Executor**（动作执行器）根据授权调用冻结 VLA 或受限原语。**Reflector**（经验整理器）在后台从实际执行记录生成和验证程序性条目。

视觉核验和执行决策在架构上统一归入 Executive。图 1 中的 `observer` 标注对应该模块内部的异步视觉核验回路。实现中由 `Observer.verify()` 通过只读接口调用冻结的视觉语言模型，返回目标状态和证据引用。Executive 通过确定性的 Evidence Gate 核查事实，并通过 Intent Gate 与动作边界的交接回执核查控制权限。控制器按其周期运行，VLA 按原生接口生成动作块，高层规划和视觉核验各自按需发起。图 2 给出这些请求与动作重叠的时序。评测分别记录控制频率、模型调用频率和并发时延。

冻结执行器使用当前观测和已经绑定的子任务指令。设 $e$ 是当前 VLA，输入处理与动作解码遵循该 checkpoint 的原生接口。每次模型输出 $K_e$ 个动作，按照后端约定执行至多 $H_e\leq K_e$ 个，阶段核查与交接在接口允许的边界发生。源模型的相机配置、动作坐标、归一化和夹爪语义在各对照中固定。系统使用任务允许的观测与反馈，评价标签在离线评分时使用。

### 2.2 三类记忆怎样参与控制

| 记忆 | 内容 | 对意图树的作用 | 更新时机与权限 |
| --- | --- | --- | --- |
| **Working Memory** | 近期图像与文字、空间测量、关键事件窗口、未决判断 | 回答分支条件所需的证据查询 | 观测可先进入缓冲，Executive 按周期、阶段和查询选择保留内容 |
| **Episodic Memory** | 当前 episode 的对象身份与角色绑定、已确认的关系和事件、顺序、计数、进度 | 约束子树实例化与后继选择，记录实际执行路径 | Executive 核查增量后更新，从有效事件重算进度 |
| **Procedural Memory** | 跨任务可复用的流程、验证、恢复、交接模板与条件执行统计，含任务专用与通用条目 | 提供可实例化的子树和执行方式，限定适用范围 | Reflector 归纳候选，验证后发布。每个 episode 读取固定版本 |

在线闭环从意图树中的未决条件开始。条件指定要观察哪个对象、哪个阶段和哪类变化，Working Memory 保留相关证据。Executive 通过 Evidence Gate 核查视觉候选判断，将有支持的事件或关系写入 Episodic Memory，并用新状态重新判断后继是否可用。比如，历史事件“本次将饼干放入烤箱”与当前关系“饼干仍在烤箱内”分别维护。之后若饼干被取出，当前关系变化，已发生的放置仍保留在事件账本。若早先的判断被证据推翻，则修正该事件及其派生进度。

跨 episode 的路径从实际执行记录开始。Reflector 根据执行条件、采取的动作、结果和反例整理带参数的程序。初始库从 EpiKnow 的已验证经验和少量人工审查模板起步，按 MAEX 的谓词及执行器接口重验。开发 episodes 提供可追溯的新增候选。历史重放检查适用条件、证据需求和误触发，闭环试验检查程序执行的实际结果与后继是否可接手。通过审核的条目按版本投入后续 episodes。具体发布规则见[附录 A](#app-memory)。

### 2.3 类脑机制关联

MAEX 借鉴目标维持、选择性更新和动作选择的分工。Planner 对应图 1 中皮层相关的任务分解与前瞻功能。Executive 将维持当前目标与选择何时更新、何时交接结合起来，借鉴前额叶与基底节参与的门控回路。Executor 对应感觉运动控制与小脑参与的快速运动调节。图中的海马提示事件与情境关联。这里采用功能类比，算法的实际分工由输入、状态和权限定义。 [工作记忆门控模型](https://pubmed.ncbi.nlm.nih.gov/16378516/)、[额叶—纹状体输出选择](https://pubmed.ncbi.nlm.nih.gov/24559680/)、[皮层—小脑运动环路](https://pubmed.ncbi.nlm.nih.gov/30333626/)

Atkinson–Shiffrin 模型启发原始观测、当前活动上下文与持久经验的保留机制。Tulving 的区分启发保留本次经历的情境与抽取跨情境知识。工作记忆理论强调保持信息的同时支持处理与决策，对应按分支需求组织的近期图文窗口。Episodic Memory 在本方案中限定为当前 episode，Procedural Memory 同时保存操作程序和作为其适用依据的通用规律。更详细的理论边界见[附录 E](#app-brain)。

## 3. 意图树与推测式规划

长程执行需要面对不同的实际结果，过去一次成功的动作序列通常只覆盖其中一条路径。MAEX 从程序性记忆复用带验证与恢复的局部控制结构，在当前子任务执行期间扩展仍未覆盖的后继。方法的设计增量在于**复用单位包含控制流和证据条件**。同一结构可以在不同对象或场景中实例化，并由后续观察决定哪条路径可以执行。

### 3.1 节点、条件与复用

意图树由全局子目标约束和当前附近的局部子树组成。一个候选节点记录语义目标、角色槽位、允许的执行方式、进入条件、预期效果与验证要求。验证节点根据结果选择后继，补证节点指定要回答的问题，恢复节点表示有界的观察或动作序列。**实现选择（choice）**在同一语义目标下比较执行方式。**结果分支（outcome）**由物理证据确定，分别处理确认达成、确认偏离和结果未决。重复任务用步骤或周期索引区分实例，进度由事件账本驱动。

程序模板注明能力范围、角色槽位、前置条件、控制结构、验证要求、交接条件和支持记录。检索先过滤不兼容的机器人、执行器和工具版本，再按当前子目标、阶段及可能的偏离查找少量条目。实例化时将程序槽位关联到已确认的任务角色与步骤，允许可安全延期的几何参数留空。只有静态能力或语义约束冲突的结构才在此阶段剔除；等待未来事件的条件保留在分支上。

**子树组合按验证结果接续。** 前一子树的已核查效果可满足下一子树的部分进入条件。尚缺信息时插入证据查询；有证据显示条件不满足时，从程序库检索能建立该条件的有界准备程序。后继若无适用模板，由 Planner 生成缺失部分。这样，每个后继保留自身的执行要求，前一步的成功可在下一步尚未就绪时独立记账。

### 3.2 饼干放置模板

以图中的 `place cookies` 为例。模板的角色槽位为 `{target, receptacle}`，当前绑定为指定的饼干和烤箱。相机几何和操作位姿在需要时由有效观测更新。

| 模板环节 | 条件与实际控制 |
| --- | --- |
| 进入放置 | 核对目标身份、持有状态、目的地和当前 VLA 的进入条件。使用绑定后的子目标发出放置指令。 |
| 核验结果 | 用释放前后及撤离过程的可见证据检查是否为目标物、是否已脱离夹爪并位于烤箱内。结果可为 true、false 或 unknown。 |
| true → `close door` | 放置事件入账。关门子树继承目标与烤箱绑定，还须核查当前在位、门状态、手臂已让开门的运动区域及控制交接。若能确认放好但手臂未退出，先以授权动作建立间隙并复核。 |
| false → `recover` | 按有证据支持的偏离选择恢复。例如仍持有但受阻时考虑退让和重新准备；确认空抓时先重新定位。 |
| unknown → `inspect` | 优先调取事件窗口或其他现有视图。只有在必须移动才能补证、且移动可行时，才提交观察动作。 |

不同任务共用控制结构时，角色槽位由 Episodic Memory 绑定，证据查询由模板指定，当前 Working Memory 提供时间对齐的图像和状态。该模板可先展开关门或补证路径。`placed` 是未来分支的条件，实际发生后才写入任务事实。

### 3.3 有界展开与提交前绑定

Planner 的请求包括任务约束、活动锚点、可用证据、记忆快照、已覆盖的分支和剩余预算。Planner 返回局部树补丁，注明新增节点、条件、证据查询和槽位。运行时关联原请求并检查字段、工具集合及引用关系。候选中的预期效果与未来假设保存在树内，正式状态依据真实观察增量更新。

首版采用阶段触发。在子任务开始后，准备较可能用到的后继；接近验证或交接边界时，检查准备覆盖；遇到未覆盖的偏离时请求修复。优先准备正常后继、经验支持的关键失败及补证路径。宽度、深度、在途请求数和推理成本设上限。结构可提前生成；提交前检查目标身份、步骤和对应控制边界，用仍然有效的几何完成绑定。已提交意图在执行期间保持实体和目标不变，同一实体的新定位可在接口允许范围内刷新。

树中的未决条件按谓词、对象、执行区间和视图产生证据查询。Working Memory 优先复用有用窗口并保留关键发生区间，减少只看最近一帧时漏掉释放和重复动作的风险。正常分支的必要条件都需得到支持，证据缺失、冲突或过期时保持 unknown。算法接口与触发配置见[附录 B](#app-runtime)。

#### 11.26v2 前瞻与程序库引用

图 1 的意图树扩展由活动意图沿成功边预备当前步及之后两步，最多三个物理目标。每层保留独立的恢复和补证路径。恢复动作后复查同一目标，补证读取当前目标的有效观测。Executive 的尝试预算约束再次调用。成功边连接既有全局计划，后继仍由前序事实、当前进入条件和交接回执共同授权。

| 加载时机 | 实现中的内容 |
| --- | --- |
| 创建 episode | 按执行器和基础程序库版本冻结一个修订。若有同任务另一 seed 的完整计划，Planner 在全局分解时读取该计划作为有序角色示例。 |
| 某层进入前瞻窗口 | 先按谓词、目标角色及步骤挂载目录。匹配的历史计划步骤作为来源引用挂到对应节点。对需要补全的层，每层向 Planner 提供至多三条恢复经验的 ID、作用范围、动作、触发结果和支持数。通用经验来自其他任务，任务专用经验限同任务的其他 seed。 |
| 恢复边界到达 | 重新使用当前绑定、爪态、模式、最新核验和交接阻塞匹配规则。任务专用匹配优先，Planner 排序只影响同一范围内的候选。匹配后才从冻结快照加载该条的完整进入条件给恢复 Planner。历史帧引用和轨迹继续用于离线复核。 |
| 未决边界到达 | 只在当前步缺少当前时刻的明确结论时使用该层的补证问题，沿用已有核验请求及 Evidence Gate。 |

请求保留各层目标、分支版本和程序库修订。迟到回执逐层核查，略过已确认的步骤，接入仍相容的后继。层内从自己的目录核对经验引用，越层引用可以单独剔除。`$drawer` 或继承目的地完成绑定时，受影响的层重新生成目录并清除旧补丁。已尝试的相同结构依赖只请求一次。近端两步有待补全节点时才启动扩展，始终限制一个在途请求，并预留一次 Planner 调用给恢复。同一个目标绑定内，单条经验进入恢复审查至多一次。经验库为空时，前瞻从基础谓词模板生成所有默认路径。

## 4. Executive 与异步执行控制

高层返回的时间和顺序与实际动作无关。MAEX 在同一意图树上维护执行与规划两个前沿，并以观察结果和分支依赖接续候选。方法的设计增量在于**把事实接纳、计划接入和控制交接定义为可分别检查的操作**。因此，高层可以准备多个条件后继，晚返回的部分只有在与有效进度相容时才能进入后续控制。

### 4.1 同树并行与更新权限

**执行前沿**记录已提交意图、活动执行实例、阶段和实际路径。**规划前沿**记录待展开或待修复的局部位置。Planner 从请求快照生成候选。Executive 的异步视觉核验接口从带采集时间与执行实例的窗口生成候选判断。VLA 返回带授权标记的动作块。Executive 分别处理这些回执，并作为当前 episode 正式状态与活动树的唯一写入者。候选可接入意图树等待证据，执行器依据已提交的授权控制机器人。

每一轮协调对外使用四类输出。

| 输出 | 内容 |
| --- | --- |
| `state_updates` | 保留窗口，接纳事实、追加修正并重算进度 |
| `tree_updates` | 接入兼容子树、剪除失效分支、更新待展开位置和执行前沿 |
| `execution_decision` | `CONTINUE`、`HOLD`、`COMMIT_NEXT`、`RECOVER` 或 `TERMINATE` |
| `async_requests` | `VERIFY`、`EXPAND`、`REPLAN` 或绑定候选版本的交接请求 |

`CONTINUE` 可与后台观察及规划并行。授权条件失效或当前动作抵达必须核查的边界时，根据执行器接口处置已经派发的动作，并在允许的位置保持或终止。协调循环不等待模型响应，控制器在等待期间按固定周期执行授权动作或预定义保持。

### 4.2 Evidence Gate 与 Intent Gate

| 门控 | 判断所依据的输入 | 正式变化 |
| --- | --- | --- |
| **Evidence Gate** | 带图像或机器人反馈引用的观察判断、对象绑定、采集区间、执行实例、谓词验证规则及已记录事件 | 确认事实、追加修正、保留未决或拒绝该判断。按物理事件身份去重后更新进度。 |
| **Intent Gate** | 候选及依赖、当前确认状态、最新几何、接收执行器条件、旧任务交接、预算和保护状态 | 在合法边界提交下一步骤并发布新执行实例与控制权限。尚未就绪的候选可保持、补证或局部修复。 |

**Evidence Gate 的具体规则。** 对 `placed(cookies, oven, k)`，异步视觉核验接收本次放置执行的开始参考、释放及撤离阶段的图像和夹爪反馈，并返回目标身份关联、释放迹象、区域关系和对应证据引用。Executive 核查来源、时间范围、对象和执行身份，并依据预注册的 `placed` 规则检查证据覆盖及冲突。若窗口观察到目标与夹爪分开且位于容器内，接受放置事件。到达结果核验点后，若清晰观察到目标落在容器外、仍由夹爪持有等反例，确认相应偏离。可用视角不足时保持 unknown。夹爪反馈支持开合状态，目标脱离与容器内关系各自需要观测支持。对过去的判断保留当时的发生区间，结合后续动作更新当前关系。

**Intent Gate 的具体规则。** `close door` 可提前处于 Prepared。放置事件确认后，关门候选还需验证任务角色与步骤、当前在位、所需几何、手臂是否已让开、接收策略进入条件及剩余预算。就绪（Eligible）表示当前检查通过。Executive 请求旧 worker 在其支持的边界停止领取新动作，收到与旧执行实例及候选版本匹配的 ACK 后，重读相关状态并复核。通过后同时发布新任务和新的控制代（control epoch），候选进入 Committed。新执行器使用最新有效观测，旧 epoch 的未发送动作和晚返回结果失效。真正动作产生的结果仍需核验。回执和复核细节见[附录 B](#app-runtime)。

这一过程允许“放置成立，关门暂缓”。它也允许“计划已准备，放置结果仍未知”。对已经确认完成的目标，旧执行器只完成约定的退出动作；重做该目标须有独立的、面向当前状态的恢复依据。

### 4.3 晚返回计划怎样接续

每条请求记录 episode、活动锚点、执行实例、原始读入的版本和证据引用。节点的核心依赖从**已注册谓词的读取项、角色槽位、任务索引和所用执行器契约**提取。Planner 可额外声明语义依赖；无法表达或核查的关键依赖触发保守重审。来自执行器适配层的几何读取项单独标注刷新条件。

| 依赖变化 | 处理 |
| --- | --- |
| 变动与候选依赖无关 | 保留候选的兼容部分，并继续核查提交条件。 |
| 同一对象移动，任务角色与步骤仍匹配 | 标记相关几何待刷新，用新的可用观测解析，保留结构。 |
| 对应步骤在补丁返回前已完成 | 用步骤或事件实例 ID 匹配实际进度，略过已完成前缀，重新锚定仍有效的未提交后继。若目标需要持续成立，检查当前关系。 |
| 对象身份、步骤、已确认结果或关键契约冲突 | 使受影响部分失效，从最近有效锚点修复。已发生的动作和现行授权按各自规则处理。 |

观察和计划按不同规则处理迟到。晚到的证据可核验其时间区间内的实际事件；当时曾持有某物体这一事实需与后续释放、滑落等动作合起来解释当前状态。晚到的计划只改候选树，保留原始请求来源和当下核查版本。该方案在受限谓词与工具范围内解释兼容性。 [Retriever 的快照兼容与执行监控](https://arxiv.org/html/2607.17213v2#S5)

| 事件 | Planner 与意图树 | Executive、记忆与动作 |
| --- | --- | --- |

## 5. 执行器选择与失败恢复

不同策略可能擅长同一个子目标的不同进入状态。MAEX 在意图树的实现选择分支中比较“**准备程序、执行器、结果核验**”这一完整方案，并以接收策略的进入条件组织恢复。其作用是将策略互补性落实为可核查的控制交接，仍由第 4 节的相同协议授权。 [Harness VLA 的 staging 与解析原语](https://arxiv.org/html/2607.08448v5)、[BATON 的进入条件与 handoff](https://arxiv.org/html/2608.16889v3)

### 5.1 选择与核验

每个执行器登记版本、原生观测与动作接口、支持的子任务、进入和持续条件、合法边界、退出效果与验证要求。首版先用一个已接通的冻结 VLA 打通主流程，随后注册经开发试验确认接口兼容且有互补迹象的第二个 VLA。图 1 中 π₀.₅ 与 OpenVLA-OFT 为候选模型示例，具体 checkpoint 和适用阶段依据平台及开发记录锁定。

正常推进时继续已授权的策略。到达子任务边界，或遇到停滞、偏离、授权失效等事件时，Executive 对同一目标枚举兼容的直接调用、补证、准备后调用和有界原语方案。先过滤对象、阶段、接口及预算冲突，再比较有同类结果记录的方案。Procedural Memory 索引子任务、阶段、进入状态、执行器版本和准备方式。优先使用目标终点一致、支持足量的条件成功统计；条件相近时参考耗时与推理开销。记录不足时使用预先核验的兼容默认方案或请求 Planner，详细平滑与加权评分作为扩展见[附录 C](#app-routing)。

选择函数返回候选方案或空结果。Executive 决定继续、保持、发起交接或提交当下合法的第一步。准备完成后根据新证据重新选择，允许恢复原模型或改由另一模型接管。记录分别标识工具返回、目标达成、交接就绪和后继结果。退让动作成功只体现它建立的局部条件，放置需另行验证。整个过程沿用同一 episode 的控制步、时间和推理预算。

### 5.2 通过准备动作创造接管状态

对接收执行器的每项进入条件，区分两类缺口。**Unknown** 表示现有证据无法判断，先复用缓冲、现有相机或目标区域，再考虑经授权的观测位姿。**False** 表示有证据显示条件不满足，检索预期效果能建立该条件的准备原语。原语检查当前前提、允许幅度、必须保持的约束和实际结果。准备后的状态由新观测确认，再逐步调用接收策略。已通过验证的前序目标及历史顺序继续约束恢复。

| 实际问题 | 初步原语 | 核验后续 |
| --- | --- | --- |
| 目标或接触结果被遮挡 | 取已有窗口，切换现有视图，`reground` | 确认身份、更新同一对象的位置或补足事件证据。 |
| 持有目标但接近受阻 | 沿已核查方向 `retreat`，必要时有限 `lift_clearance` | 核验持有状态、间隙及已完成关系。 |
| 某策略需要不同的腕部接近姿态 | `adjust_pose` / `stage_for` | 核验接收策略的进入区域、可见性和姿态。 |
| 当前能力不适合，或相同状态持续失败 | 查找兼容的另一 VLA 或已验证的替代原语 | 复核已知故障、执行边界与累计尝试，避免来回重复。 |

纯读图和裁剪可与控制并行；改变机器人姿态以观察时按普通动作提交。预检、真实执行和效果核验（preview–execute–verify）适用于原语，也适用于 VLA 的接口调用与结果检查。受阻时移动到新的局部进入位姿，场景与预算继续累计。更完整的停滞判定、重试规则与可选感知工具见[附录 C](#app-routing)。 [Auriga 的执行预检与效果核验](https://arxiv.org/abs/2611.01112v1)

## 6. 实验设计与实现顺序

主实验复用 EpiKnow 的 MuJoCo/RoboMemArena 部署，覆盖对象绑定、顺序、计数、遮挡和多对象操作。按结果分歧程度和对历史的依赖划分任务，并用受控扰动和真实执行事件产生偏离。通过主实验后，再在已有 Franka FR 3 任务验证接入。记录开发与评测所用的任务、种子、感知权限和硬件配置。

| 对照 | 主要隔离的变量 | 首要观测 |
| --- | --- | --- |
| EpiKnow 原始配置 vs MAEX | 相对同一基础的联合增量 | 任务与阶段成功、墙钟、推理成本 |
| 相同经验的文本检索 vs 子树实例化；固定条件树作补充 | 经验的复用形式与按任务扩展 | 边界前可用后继、规划开销、任务成功 |
| 同一棵条件树的串行扩展 vs 执行期间扩展；简单单后继异步作补充 | 规划重叠，以及准备多结果的价值 | 实际边界等待、无效推测开销、成功与成本 |
| 整份丢弃或重建晚返回规划 vs 局部接续 | 候选依赖与保留范围 | 补丁接入和实际提交比例、错误接纳、重建成本 |
| 事实确认后直接切换 vs 两道门控 | 独立交接检查 | 错误交接、重复动作、事实错误与漏计。在仿真中诊断。 |
| 同池固定模型、简单经验路由、完整准备与选择 | 策略池、进入状态准备和事件触发切换 | 进入条件建立、接收后继成功、额外动作和推理成本。作为扩展实验。 |

机制对照共享模型、工具、感知权限、任务种子及可用预算。文本与结构化经验使用同一来源案例、相同适用信息与工具候选，记录格式带来的 token 差异。默认在测试前冻结程序库、统计和参数。先报告真实服务时延，再对 Planner 和视觉核验接口分别注入延迟与抖动，记录共同加速器上的资源竞争。所有保持、废弃推测、恢复和重试计入成本。事实与交接正确性由独立离线标签复核。

实现先打通一条完整链。① 测量原 EpiKnow 的控制时钟与动作边界，固定一个执行器。② 实现对象、证据与事件记录及小型程序库，跑通图中的放置—关门链。③ 接通异步返回、两道门控和交接，再构造迟到与偏离测试。④ 完成两项核心贡献的匹配对照。⑤ 增加经验证的第二个 VLA、恢复原语和跨任务巩固，单独测其边际收益。首版的接口、日志和配置见[附录 B](#app-runtime)，评测口径见[附录 D](#app-evaluation)。

### A. 记忆记录与程序库发布

Working Memory 用近期环形缓冲与带引用的事件存档组织信息。连续采集带控制步与时间戳的相机图像和机器人反馈。周期采样、夹爪变化、阶段事件、图像变化或长期无进展触发候选窗口，树上的证据查询指定要保留的前后片段。普通请求可合并，关键窗口依执行实例独立记录；被已确认事实引用的必要证据保留可访问位置。各相机分别记录采集时刻，按窗口对齐使用。

| 数据对象 | 最少记录 | 写入与读取 |
| --- | --- | --- |
| `Observation` / `EvidenceWindow` | 窗口与各帧 ID、控制步、采集时间、相机、图像引用、末端与夹爪状态、执行 ID 及阶段 | 控制器记录实测反馈。Executive 选择窗口供视觉核验接口和 Planner 读取 |
| `ObservationJudgment` | 原请求 ID、目标与执行 ID、时间区间、谓词判断、支持及冲突证据、未决问题 | 视觉核验接口提出，Executive 按预注册规则核查 |
| `FactDelta` / `Event` | episode、谓词、对象参数、取值与确认状态、事件区间、执行或周期 ID、证据引用、修正指针及状态版本 | Executive 追加更新并合并重复报告，派生顺序和计数 |
| `ProcedureTemplate` | 版本、适用范围、角色、前置条件、子树、结果核验、保持与交接条件、支持／反例及审核状态 | Reflector 生成候选；验证后发布，Planner / Executive 读取 |

示例事实记录如下。`released`、`inside` 等判断各自保留证据引用，最终接纳规则由注册谓词定义。

```json
{
  "claim_id": "claim_024",
  "episode_id": "ep001",
  "execution_id": "place_cookies_attempt_1",
  "predicate": "placed",
  "arguments": ["cookies_01", "oven_01", "place_cookies_step_1"],
  "value": "true",
  "status": "candidate",
  "observed_steps": [210, 240],
  "evidence_refs": ["front_210_240", "wrist_210_240", "gripper_210_240"],
  "supersedes": null
}
```

同一次物理放置由对象、任务步骤、执行实例和重叠区间关联为唯一事件。计数任务可在一个执行实例内发生多次事件，另用完整动作周期的起止、转折和对象身份区分。事件合并所依据的是时间和阶段匹配。观测重叠且无法区分周期时保留未决。修正以追加记录连接被撤销的判断，重算受影响的派生进度；当前关系优先依据可追溯的最新有效观察及相关动作更新。

启动库来自已验证的 EpiKnow 经验和少量经人工核对的流程。第一批模板应以放置核验、抓取结果核验、补充观察和受阻后准备为主。Reflector 读取实际尝试的起点、判断依据、执行方式、事件窗口、结果与后续恢复，归纳适用条件、参数槽位、可执行结构和反例。候选模板可以描述未来分支；支持案例只来自已经发生的执行。任务专用条目保留任务规则，通用条目以角色和可观察条件表达适用范围。

| 验证阶段 | 操作及首版发布标准 |
| --- | --- |
| 结构检查 | 代码核对谓词、执行器版本、角色映射、预算及后继引用。人工审查新谓词或原语的可观测性、参数边界和效果定义。 |
| 历史重放 | 在带支持案例与反例的已记录决策点，比较当前库和候选库。检查适用判断、应请求的证据、应保留的进度，以及能否定位后继。需覆盖规定的正例与有代表性的混淆反例，并满足开发前规定的误触发上限。 |
| 匹配闭环验证 | 在与模板来源分开的开发 episodes 中，以匹配的起始条件、工具与预算比较候选和基线。以实际目标与后继可执行验证预期效果，报告已完成目标被破坏、错误目标、未决和失败。至少达到预设的支持数、相应收益及回退条件。 |
| 发布 | 保留模板版本、验证记录和适用范围。候选遇到冲突则修订或缩小范围。评测前冻结发布版本；本 episode 发现的不适用实例先局部禁用，归档作后续验证。 |

支持数、阈值与回退规则在开发实验开始前定义，使用与最终评价分开的数据。重放可以检验选择与条件解释，改变动作后的结果由闭环测量。

### B. 运行接口、计划补丁与交接算法

一个子树以节点表和父子关系存储。正式请求与结果拥有稳定 ID。准备、合并、剪除、刷新、移根和修复只改变外部控制结构。恢复与重复实例按任务步和尝试索引创建，已执行分支按事件存档。

| 接口 | 最少字段与输出 |
| --- | --- |
| `PlanRequest` | 框架内的 `episode_id`、`request_id`、`tree_id`、锚点、当前执行实例、来源快照版本、已知依赖版本、程序库版本、已引用证据及预算 |
| `TreePatch` | 请求 ID、作用范围、节点与边、槽位和绑定要求、受限谓词、证据需求、预期效果、模板版本和适用的执行方式。运行时关联不可变的原请求元数据。 |
| `IntentionNode` | 稳定目标及步骤实例 ID、状态、动作/验证/补证/恢复类型、语义绑定、进入与保持条件、验证要求、预期效果、后继、可刷新参数和依赖 |
| `ActiveTask` | `intent_id`、`intent_revision`、`execution_id`、`control_epoch`、执行器及版本、具体绑定与观察配置、阶段、允许继续范围、必须验证的边界与停止条件 |
| `HandoffRequest` / `Ack` | 旧执行实例及 epoch、候选节点版本、许可边界、回执到达时刻与最后一个已授权动作的索引 |
| `ToolResult` | 执行 ID、采集时刻、请求/响应、`command_status`、待核验的效果、`goal_achieved`、`handoff_ready`、后继结果引用 |

核心谓词以 `predicate(arguments)` 形式注册，注册表声明其读到的实体、事件、几何或契约字段。编译依据谓词参数、目标角色槽位和动作契约自动提取依赖。例如 `in(cookies, oven)` 依赖两个对象身份和当前关系，`placed(cookies, oven, k)` 依赖已确认的第 k 步事件，`door_pose(oven)` 只在身份不变且观测有效时允许刷新。请求保存当时的版本。补丁接入时记录最新核查结论和版本，源记录保留供审计。若树已修复或对象已改变，按依赖逐分支核查，超出锚点或已提交范围的修改拒绝接入。

设 $v_t(p)$ 是谓词 $p$ 在时刻 $t$ 根据最新有效证据得到的三值判断。对待提交的物理步骤 $n$ 定义

$$
\operatorname{Ready}(n,t) =
\operatorname{Compatible}(n,t)
\land \operatorname{Grounded}(n,t)
\land \bigwedge_{p\in\operatorname{Pre}(n)}[v_t(p)=\mathrm{true}]
\land \operatorname{BudgetOK}(t)
\land \operatorname{ProtectionOK}(t).
$$

`Compatible` 包括当前语义绑定、步骤和显式依赖；`Grounded` 检查需要的几何、坐标与时效；`Pre` 包含任务条件和本方案当前一步的接收条件。意图提交还需要与候选版本匹配的控制边界及 ACK，并在发布之前重新计算 `Ready`。首个动作没有旧控制者，直接核查进入条件与权限。获取新图像的纯读操作只提交 `VERIFY` 请求；涉及机械臂动作的补证步骤也使用该协议。

**算法 1 意图树展开。** 对每个受预算约束的前沿，读取请求快照，依次检索、过滤和实例化可复用程序。检查关键结果是否已有验证和后继。缺失时调用冻结 VLM，限定工具名称、谓词集合、所请求的锚点与子树规模。合并程序与补全后，返回带来源的未提交补丁。运行时检查并接入，接入过程见 §4.3。

```text
expand(request):
    templates = retrieve_compatible_templates(request.snapshot, request.frontier)
    fragment = instantiate(templates, request.roles, request.step_constraints)
    missing = find_uncovered_outcomes(fragment, request.frontier)
    if missing and planning_budget_available(request):
        fragment = merge(fragment, frozen_planner(request, fragment, missing))
    return validate_and_package(fragment, request)
```

**算法 2 Executive 的一次调度。** 已获授权的控制循环独立运行。本轮只处理已返回消息，状态更新先于重评估候选。方案选择函数仅返回候选或空值。

```text
tick(returned_messages, actual_feedback):
    state_updates = ingest_feedback_and_retain_windows(actual_feedback)
    state_updates += admit_observation_deltas(returned_messages)
    recompute_progress_from_valid_events()
    tree_updates = reconcile_returned_patches(returned_messages, current_state)
    tree_updates += update_frontiers_and_invalidate_dependencies(current_state)

    if protection_triggered() or budget_exhausted() or task_satisfied_at_stop_boundary():
        return updates_with_termination(state_updates, tree_updates)

    async_requests = []
    decision = continue_within_valid_authority_or_hold()
    if at_selection_event():
        candidate = select_candidate(tree, current_state, fixed_procedure_version)
        step = first_admissible_step(candidate)
        if is_read_only_query(step):
            async_requests += schedule_verification(step)
        elif is_physical(step):
            if boundary_ack_matches(step) and ready_now(step):
                decision = commit_with_new_epoch(step)
            elif ready_now(step):
                async_requests += request_handoff_if_needed(step)

    decision = restrict_to_authorized_prefix_during_handoff(decision)
    async_requests += schedule_required_verification_and_expansion()
    return state_updates, tree_updates, decision, async_requests
```

`at_selection_event()` 包括子任务间边界、偏离、相关条件更新或等待中的交接回执。提交物理准备时输出 `RECOVER`，提交正常后继时输出 `COMMIT_NEXT`。同一资源只有一个有效 epoch；交接挂起时旧 worker 只完成约定前缀。若回执返回后候选已失效，撤销挂起请求，重新核查当前允许的动作或保持。继续上一方案须重新检查授权与阶段，回执与授权记录按原实例管理。控制适配器派发前再次检查 epoch 和预算。若只能在较粗边界停下来，则将规划步骤的验证和提交布置在该边界，安置预定义保持行为。

| 运行部分 | 时间与队列规则 |
| --- | --- |
| 控制及执行 | 以物理周期推进控制；VLA 推理与执行按各自服务和原生 chunk 接口运行。旧 chunk 或不再有效的观测输入按契约作废。 |
| Executive 主循环 | 优先处理保护、结果核验、交接、普通观察。一次内部更新序列只由该循环发布正式状态。对外写入日志和控制权。 |
| Executive 的异步视觉核验 | 队列有界，合并重复的普通请求，按条件和阶段保留关键窗口。超时后保留未决，由 Executive 在必要边界复核动作授权。 |
| Planner | 首版单个在途请求。按阶段、缺口与预算触发并去重。可用 $\widehat T_{\rm boundary}\le L_{\rm planner}^{95}+m$ 做触发参考，实际时延经开发测量。 |
| Reflector | 读取已归档经验。验证和发布在后台及独立开发运行中进行。 |

最小配置记录模型与 checkpoint、原生观测与动作适配、可用相机与控制周期、各模型 $K_e$ / $H_e$、动作中断与保持接口、窗口长度、语义超时、树宽与深度、谓词规则、程序库版本、总控制/时间/推理预算和每步重试上限。首版可从三类结果和一至两步计划后继的范围开始试验，以覆盖率和废弃计算决定调整。具体 checkpoint、周期和阈值随接通的实际平台确定。

### C. 执行统计、恢复原语与切换约束

候选方案 $\rho=(n,e,r,v,z,D)$ 对应语义意图、执行器、可为空的准备子树、结果核验、需保持的交接状态与依赖。统计上下文 $x$ 包括子任务与阶段、已确认进入状态、已知故障及相关接口版本。组合统计以匹配的评估终点为单位。记录局部成功、交接就绪与后继结果，按需要使用联合结果。不同准备、执行和后继间的相关性由实际组合运行反映。

未调用记录与已尝试的失败分开。证据不足是未决，外部中断是截断。样本支持按实际执行实例记录，统计推断按 episode 聚类。支持量不足可在预先声明的层级回退（进入状态、子任务阶段、任务家族）。有上级数据时可用固定平滑强度 $\eta$；根层使用对应已判定样本频率：

$$
\widehat p(\rho,x)=
\frac{s(\rho,x)+\eta\widehat p(\rho,\operatorname{parent}(x))}
{s(\rho,x)+f(\rho,x)+\eta}.
$$

没有有效统计时使用已验证且兼容的默认候选，或发出局部修复请求。加权多指标排序可作为后续消融，比较同一目标与评估终点，在预算为正且有统计支持时使用

$$
J(\rho,x)=\widehat p(\rho,x)
-\lambda_t T_{\rho}/B_{\rm time}
-\lambda_c C_{\rho}/B_{\rm infer}
-\lambda_s\mathbf 1[e\ne e_{\rm active}]
-\lambda_u U(\rho,x).
$$

$T_{\rho}$ 涵盖准备、推理、核验与交接，$C_{\rho}$ 按相同的推理成本单位计量，$B_{\rm time}$ 和 $B_{\rm infer}$ 分别为剩余时间及推理预算。可沿用 v2.5 的不确定性项 $U=[\eta/(N+\eta)+r_{\rm unresolved}+\ell/L]/3$，其中 $N=s+f$，$r_{\rm unresolved}$ 为未决与截断占比，$\ell/L$ 为相对回退深度。各权重与阈值在开发集确定。静态成本或偏好分数用于排序，控制调度仍核查当前进入条件与预算。对同一意图的有效当前方案可设切换裕量与驻留时间。确认失败或保护触发时优先处理停止与恢复；进入新子任务允许重新选择。评测前固定选择规则和统计版本。

| 原语种类 | 受限参数和要求 |
| --- | --- |
| `observe` / `reground` | 相机、ROI、窗口与对象引用。重用已采集信息优先，其次新取现有视角，运动观察须取得控制权。定位关联时刻、相机外参和同一对象身份。 |
| `retreat` / `lift_clearance` | 已核查的可通行方向、位移上限、持有与接触状态。执行后检查实测退让、剩余空间和保持条件。 |
| `adjust_pose` / `stage_for` / `move_to_observe` | 局部目标位姿、接近区域、可见性和所需间隙，从可用几何进入经验证的控制适配。结束后复核接收策略进入状态。 |
| 可选缓冲放置、重抓与显式抓放 | 任务允许且有可检验中转区时启用。可用分割和深度得到点云或位姿，通过逆运动学与已有控制器执行，分别记录目标达成和中间效果。 |

每个运动原语声明前置与保持条件、预期效果、参数范围、停止条件和实际核验要求。实际运行时可选用开放词汇定位、分割、深度反投影、局部图像差分与光流。模型和输入在比较中固定，选择经验证的工具链。图像变化用于提出观察或停滞候选。对预期有单向运动的阶段，比较实际执行区间内的命令位移与观测位移，结合时间对齐、持续窗口和已知执行阶段提出受阻判断。接触保持或往复段按各自的进展规则处理。

重试需要符合可观察条件。优先确定目标是否已达成，再区分证据不足、进入条件缺失和当前能力局限。若准备后出现可核查的视野、间隙或接近方向改善，重评原模型与替代模型。为同一目标记录“执行器、阶段、故障、进入条件与准备”的失败指纹及累计上限，几何微小抖动不视为新状态。所有方案继续使用相同的对象绑定、已验证进度和 episode 预算。

### D. 评测口径、日志与实验边界

| 变量 | 统计口径 |
| --- | --- |
| 任务与阶段完成 | 用基准评价及独立事件复核检验任务目标与顺序、身份、计数或最终关系。单列系统自报完成与评测结果不一致的比例。 |
| 边界等待 | 记录当前子任务动作或允许的退出段到达边界至下一子任务首个动作的墙钟间隔。区分等候选、等证据、等准备、等 ACK、参数刷新、接收策略推理和必要物理稳定时间。记录重叠原因与实际控制时间。 |
| 前瞻覆盖 | 回溯独立标签指示的真实结果，统计其所需、能力适配且证据可核查的结构是否已在边界前准备。另报实际取得授权的比例。 |
| 补丁接续 | 在通过结构与能力检查的返回结果中，记录拥有至少一个通过当前状态核查的未提交节点的比例。统计接入、实际提交和错误接入，报告重复规划和废弃候选开销。 |
| 记忆与交接 | 按事件和边界机会统计错误事实、漏计／重计、过期结果、错误提前交接、已完成目标重复执行。用人工或独立离线标签复查。 |
| 恢复和使用成本 | 分开记录准备效果、接管就绪和接收策略结果；记录请求数、图像、tokens、端到端时延、排队、冷启动、资源并发、等待与动作步。报告所有 episode，离线构建及验证开销另列。 |

仿真按控制周期与墙钟节拍推进，推理期间记录授权动作或保持。服务时延、排队、证据年龄和物理控制时间分别记录。边界等待由多个先决条件的就绪时间及派发决定。若候选、证据、最新几何和交接条件分别在 $t_P,t_E,t_G,t_H$ 达到可用，首个动作不早于这些时刻的最大值。若依赖刷新或先决条件后来失效，按重新满足的时刻记录。

使用配对 seed，以任务或 episode 为统计单位报告不确定性。程序库构建、适用性验证与最终测试使用分离数据。报告按任务族和扰动分类的结果。策略互补和接管测试平行安排，分别在相同初始条件及已有执行前缀的实际中间状态进行。在同一评测 episode 内按选定分支执行，分支比较用独立闭环试验。额外诊断可选择去掉晚绑定、树引导证据选择等单一机制，固定模型和感知权限。

日志关联 episode、对象、步号、执行实例、节点、请求、来源快照、证据、结果、取消原因与 epoch。时刻至少覆盖采集、发起、返回、核查、动作开始和结束。控制循环、普通语义队列与 Planner 均记录预算消耗。复核优先覆盖重复事件、身份变化、几何过期、当前关系丢失、ACK 晚到和预算中止等会改变行为的场景。
