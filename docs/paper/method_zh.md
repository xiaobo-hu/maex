# 3 方法

我们提出 RoboAgent-Evolve，一个连接任务内状态判断与跨任务经验复用的长程机器人智能体框架。方法从分层执行中的一个问题出发：高层 Agent 每次决策后，底层视觉语言动作模型（VLA）会连续执行多个动作块；在两次高层决策之间，抓持、接触和物体位置可能发生变化，仅查看执行结束时的图像难以还原这一过程。为补充这段执行期间的信息，我们在执行层引入基于视觉语言模型（VLM）的观察器，持续接收观测流并按窗口描述变化，再将这些描述与机器人事件及首尾观测组织为调用内工作记忆。高层 Agent 结合任务计划、工作记忆与历史账本判断进展并选择恢复。离线阶段通过自动事件提取与外部维护者复核，从记录中整理状态—决策—结果关系，将跨 episode 规律转为经过验证的程序性指导。两条流程分别服务当前执行与未来决策，均不更新底层 VLA 参数。

## 3.1 记忆驱动的长程机器人执行框架

我们考虑由语言指令指定的部分可观测机器人操作任务。智能体通过外部与腕部相机观测环境，并读取末端位姿、夹爪等机器人状态，在有限交互预算内完成多个具有依赖关系的子目标。RoboAgent-Evolve 将高层任务管理与底层动作生成解耦：高层 Agent 根据执行证据和任务历史进行规划、状态判断与工具选择，冻结的 VLA 根据当前子任务生成连续动作。

**基于工具交互的执行闭环。** 高层 Agent 按照 ReAct 式的“推理—工具调用—反馈”循环组织执行。任务开始时，运行时获取初始观测，Agent 据此创建有序计划，标记已完成、当前执行和待执行的步骤。每轮决策中，Agent 结合当前计划、最新执行证据、任务内历史及已加载的程序性 Skill，选择下一次工具调用。工具结果返回后，新的观测和执行记录进入后续推理，使下一步选择取决于实际反馈，而非预先固定的动作序列。

Agent 通过以下工具管理任务与机器人执行：

| 类别 | 工具 | 在闭环中的作用 |
| --- | --- | --- |
| 任务规划 | `create_task_plan`、`advance_task_plan`、`repair_task_plan` | 创建子任务序列、推进已完成步骤，或重开失效的前置步骤 |
| VLA 执行 | `execute_vla` | 根据当前步骤的语言指令执行一段局部操作，返回执行结果与过程记忆 |
| 位姿恢复 | `restage_vla`、`adjust_ee_pose`、`return_to_home` | 通过固定回撤、局部末端调整或返回初始关节位姿，改变后续尝试的起始条件 |
| 夹爪操作 | `open_gripper`、`close_gripper` | 显式控制夹爪开合，配合操作与恢复 |
| 任务结束 | `finish` | 提交终态判断与摘要，结束当前 episode；成功判断可由环境验证器核验 |

观察贯穿这一循环：初始观测提供规划起点，物理工具返回新的观测和机器人执行结果，后台 Observer 补充 VLA 执行期间的视觉变化。当前主循环自动提供这些观察信息，Agent 无需额外调用独立观察工具。一次 `execute_vla` 调用可以包含多个动作块，每个动作块根据新观测生成；Runtime 限制调用预算、工作区边界与工具前置条件。调用结束意味着控制权交回高层，子目标是否完成仍需进一步判断。

**先解释执行结果，再选择下一行动。** 为使行动选择建立在明确的状态判断上，我们在 VLA 执行和位姿恢复反馈后插入独立的状态反思（Grounded State Reflection）。高层模型先在不提供工具的回合中检查执行前后证据，描述发生了什么变化、当前目标是否有完成依据，以及哪些条件仍不确定；随后恢复正常工具集合，结合反思、计划、历史和 Skill 选择下一动作。反思与决策使用同一个高层模型，分别保存状态解释和行动选择。

这一过程可概括为：

```text
初始观测 → 创建任务计划
                  ↓
结合计划、历史、最新证据与 Skill 选择工具
                  ↓
执行工具 → 返回结果并更新任务内记录
                  ↓
VLA 执行或位姿恢复后：无工具状态反思
                  ↓
继续执行 / 推进计划 / 修复前置步骤 / 物理恢复 / 结束任务
                  └→ 下一轮工具调用与反馈
```

独立反思由 `execute_vla`、`restage_vla`、`adjust_ee_pose` 和 `return_to_home` 的非错误工具返回触发，并在任务循环继续时进行；计划调整和单独夹爪调用的反馈直接进入正常决策。通过这一安排，Agent 能够区分工具执行完成、物理条件恢复与任务目标达成。例如，抓持条件丢失时，计划修复负责重开抓取步骤，后续 VLA 或机器人工具负责实际恢复；只有获得相应完成证据后，Agent 才应推进计划。

## 3.2 从执行过程观察到任务状态判断

**低频决策留下的观测空隙。** 上述分层结构使高层推理无需介入每一个控制步，但也使它无法在一次 VLA 调用内逐步检查环境。例如，对象可能在移动途中脱离夹爪，或在执行后被遮挡；结束图像能够提供当前可见状态，却未必能说明中间发生了什么。仅依赖调用边界的观测，会缺少区分持续持物、抓取失败和中途掉落所需的过程线索。

为此，我们在底层执行期间引入基于 VLM 的观察器（Observer）。它与 VLA 执行并行接收视觉观测，根据当前子任务描述局部变化，为下一轮高层推理补充过程信息。Observer 的职责是观察和描述；计划完成判断、下一动作选择与恢复调度仍由高层 Agent 负责。这里的持续观察指持续接收执行观测流并进行窗口化推理，不要求 VLM 对每一帧推理，也不保证捕获所有瞬时事件。

**窗口化视觉描述。** 为控制视觉推理开销，Observer 在一次 VLA 调用中积累足够的新观测后进行至多一次中途评估，并在调用结束时评估尚未处理的尾段。中途请求与尾段请求顺序执行，覆盖不重叠的区间；高层获取工具返回前，运行时等待本次观察结果收集完成。因此，每次调用至多包含两次视觉评估，较短调用可能仅有尾段评估。

每个窗口优先选取区间首尾图像，并在预算允许时补充夹爪转换关键帧；每个被选时刻使用可用的外部和腕部视角。夹爪事件由开合命令与实际位置变化共同定位：在同类夹爪命令区间内，以转换基准位置为参照，记录位移超过阈值且变化最大的时刻。它提供检查抓取或释放过程的时间线索，事件本身不证明对象已被抓住或释放。

Observer 结合当前指令、窗口采样图像与上一条视觉描述生成新的文本描述。上一条描述用于衔接时间上下文，并作为未经验证的模型输出保留；当前图像仍是判断新变化的依据。这样，高层 Agent 可以访问执行中段与尾段的可见变化，而无需处理完整图像序列。

**调用内多模态工作记忆。** 在第 $k$ 轮 VLA 调用结束时，将窗口描述、执行诊断及首尾观测共同组织为

$$
W_k=(V_k,D_k,I_k^{\mathrm{start}},I_k^{\mathrm{end}}),
\tag{1}
$$

其中 $V_k$ 为带有观测区间的视觉描述，$D_k$ 为机器人起终点状态、夹爪事件、动作块使用量与停止原因，$I_k^{\mathrm{start}}$ 和 $I_k^{\mathrm{end}}$ 为调用前后的双视角图像。这一表达描述提供给高层的证据组合；实现中，结束观测与调用内记忆一起由工具结果提供。视觉描述和机器人事件保留各自的来源及观测序号，便于核对描述对应的执行区间。

高层通过首尾原图及基于像素差分的变化高亮检查直接视觉证据，通过 Observer 文本和夹爪事件访问中间过程。变化高亮只标识像素差异，不直接表示任务进展；中途关键帧不直接追加到高层图像上下文。$W_k$ 在调用结束后固定，下一次调用重新收集。它负责组织局部执行证据，跨调用的历史利用由下面的账本支持。

**任务内历史与状态反思。** 为保留已经完成的操作和此前出现的事件，我们在工具调用结束时，将工具名、关键参数、结果及决策摘要追加到 episode 历史账本。在后续推理中，较早的工具结果由紧凑事件记录替代，同时保留最新物理执行的多模态证据。该压缩过程不额外调用模型；其中的决策摘要仍是 Agent 当时的陈述，而非经过独立核验的环境真值。账本在新 episode 开始时清空，完整执行记录另存用于离线追溯。

第 3.1 节的状态反思使用这些记忆与最新视觉证据解释执行结果。反思回合保留相关历史，并从工具文本中移除部分计划与执行预算字段，使模型侧重物理变化、目标完成证据及不确定性；随后恢复正常计划上下文进行工具选择。Observer 提供执行期间的局部描述，高层 Reflection 则结合这些描述、首尾观测和历史判断当前任务状态，两者在观察范围与职责上互补。

任务状态判断因此由任务计划、调用内工作记忆、历史账本与反思共同支持：计划指出正在完成什么，过程记忆提供刚才发生的变化，历史账本保留此前的执行结果，反思对这些信息作出当前解释。物理状态、历史完成事实和计划进度需要分别核对；它们没有被合并成一个自动维护全部对象状态的结构化世界模型。这些记录同时为离线分析提供“当时看到了什么、如何判断、选择了什么及随后发生了什么”的来源。

## 3.3 跨 episode 经验形成与管理

记 $S_r$ 为第 $r$ 轮离线更新后的程序性指导；它在单个 episode 内固定。跨 episode 学习通过更新 $S_r$ 改变后续决策。我们基于执行证据审核局部判断与行为，将具有明确适用条件的经验积累为持久知识，并通过对照执行检验相应指导的有效性。经验知识与程序性指导的分离沿用 WikiSkill 的组织方式。[WikiSkill](https://arxiv.org/html/2608.27454v1)

**从任务内记忆组织局部经验。** 经验提取关注任务阶段变化、执行失败、计划修复以及判断与结果不一致的片段。明确的阶段变化和执行失败由程序提取，复杂事件的窗口选择和解释可由外部维护者复核。对于选定窗口，我们进一步按实际工具调用对齐第 3.2 节产生的工作记忆、历史账本、状态反思与计划记录，组织“决策前记录—实际决策—执行反馈—执行后记录”。这一对齐过程直接复用在线产生的信息，不额外调用模型重新解释图像或补写任务状态。

$$
\begin{aligned}
x_c &= (B_c^{-},u_c,R_c,B_c^{+}),\\
e &= (\nu,[c_s,c_e],\{x_c\}_{c\in\mathcal C_e},\lambda),
\end{aligned}
\tag{2}
$$

其中 $\nu$ 标识来源 episode 及执行记录，$[c_s,c_e]$ 为事件窗口，$\mathcal C_e$ 为窗口内关联的工具调用，$\lambda$ 保留经验的学习资格。对调用 $c$，$B_c^{-}$ 包含此前最近的计划、工作记忆、机器人状态与反思记录，以及截至该调用之前的历史账本；$u_c$ 保存实际工具名称、参数和已有决策摘要；$R_c$ 为本次工具的实际返回；$B_c^{+}$ 仅包含本次调用产生或与其关联的计划、工作记忆、机器人状态、反思和新增账本条目。多调用恢复过程逐次展开，避免将“修复计划”和“后续重新抓取”混为同一结果。

前态只引用调用发生之前的记录，后态只关联本次返回，不以 episode 最终计划或后续结果回填。若计划调整或夹爪操作没有产生新工作记忆、若某次调用没有关联反思，则显式保留缺失；历史记忆仍附有原调用身份，不能冒充新观察。程序仅对两端均有记录的计划或机器人字段计算差异，不把未提及的任务条件视为保持不变。$B_c^{-}$ 与 $B_c^{+}$ 因而是有时间边界的状态记录集合，而非完整物理状态，也不等同于逐字复原当时的模型输入。

**证据来源与学习资格。** 对齐后的记录保留证据与解释的区别：工具返回、计划更新和机器人诊断用于核对实际执行，Observer 描述、Reflection 和决策摘要保留为模型当时的表述。每项内容关联来源调用及原始记录位置，即使描述彼此冲突也不由整理程序裁决。任务语义仍以已有文本判断保存，不自动转换为完整的对象状态标签。例如，`repair_task_plan` 返回成功可以确认计划已更新，但不能据此认定抓持条件已恢复；后者需要后续执行反馈支持。

经验整理沿用来源事件的学习资格，不因记录变得完整就自动允许其用于指导生成。未经审核的失败、计划修复及由实现缺陷导致的异常保持隔离；缺乏证据时保留未知归因。局部行为的评价依据其对应后果，episode 最终成败不能直接替代局部归因。在 RoboMemArena 中，隐藏阶段信息可用于事件定位和离线核验，但与上述决策上下文分开保存，不参与在线决策，也不作为 Agent 当时已知的状态。视觉材料需要时可通过来源记录回查；本流程不要求每条经验都重新接受外部图像判读。

**跨 episode 规律归纳与指导提炼。** 外部维护者以对齐后的经验为依据，比较不同 episode 中相似条件下的状态判断、实际决策与执行反馈，将共同关系及其反例组织为持久 Wiki Pattern。每条规律记录适用条件、支持的经验与调用、观察到的结果及不适用情形。程序核验来源身份、字段引用与基本学习资格，语义归纳和范围审查由维护者完成。例如，已有记录可揭示“决策摘要称准备倾倒，实际工具却将倾倒步骤标为完成”的不一致；这类关系可以直接由计划、摘要和工具返回核对，无需额外推断物体真值。

同一 episode 中的重复事件只计为一个来源，支持案例与边界案例分别解释。来源覆盖表明规律具有提出和检查的依据，不等于它已经提高任务成功率。正式候选需通过已有成熟度与来源资格检查；其中 probable 要求至少两个可学习 episode 支持。新形成的 Wiki 条目先作为候选观察保留，不自动获得正式验证资格，适用范围也不因出现相似表述而直接扩大到全部任务。

为使积累的规律作用于在线决策，我们将其提炼为条件化的自然语言规则，作为程序性指导输入规划器。候选指导 $S'_r$ 针对一个局部决策问题修改已有规则，按“触发状态条件 → 决策 → 停止或重新判断条件”组织。它指导何时继续执行、推进计划、修复前置步骤或进行恢复，具体机器人动作仍由冻结的 VLA 和工具完成。在线规划器显式加载一份当前指导，完整离线经验与知识库不直接进入在线上下文；任务内历史账本仍照常参与决策。经验归纳提供干预假设，行为修改的有效性由后续验证决定。

**决策回放与闭环验证。** 我们采用两阶段验证，分别检验候选对局部决策和完整任务执行的影响。首先，从历史轨迹构造决策案例 $z$，包含任务、计划、历史摘要、状态描述及允许动作集合 $\mathcal A_z$。在相同文本上下文下，比较原指导 $S_r$ 与候选指导 $S'_r$ 所选择的动作。记 $b_z(S)$ 为动作及其必要参数是否符合 $\mathcal A_z$，候选需改善整体匹配结果，并保留原有正确决策：

$$
\sum_z b_z(S'_r)>\sum_z b_z(S_r),
\qquad
\forall z,\ b_z(S_r)=1\Rightarrow b_z(S'_r)=1.
\tag{3}
$$

决策回放仅在固定文本状态描述下检查工具及必要参数，不重新执行视觉识别或机器人动作。通过的候选进一步接受包含视觉感知与物理交互的闭环检验：在匹配任务、seed、模型、运行时与评估器版本及执行参数的条件下，对原指导和候选指导开展配对执行，并将经验来源轨迹与验证运行分离。

对于 $m$ 个配对，定义 $Q(S)=(\sum_{j=1}^{m}\mathrm{TSR}_j(S),\frac{1}{m}\sum_{j=1}^{m}\mathrm{CSR}_j(S))$，其中 TSR 为整任务成功指示量，CSR 为阶段完成百分比。候选接受准则为 $Q(S'_r)>_{\mathrm{lex}}Q(S_r)$，即优先比较整任务成功数，再比较平均阶段完成度；同时要求原指导成功的配对在候选下仍然成功，且评估至少包含两个不同的候选运行。

配对允许复用同一原指导运行作为锚点，因此 $m$ 表示比较对数，不一定对应 $m$ 个独立原指导样本。只有两阶段验证及候选资格检查均通过，才将 $S_r$ 更新为 $S'_r$。未通过验证的修改及其结果保留为维护记录，后续是否形成可学习经验仍需资格审核。该接受准则防止验证配对中原有整任务成功退化为失败，但不保证所有未成功任务的阶段完成度均不下降；对新初始状态或新任务的泛化需由留出评测检验。

**算法 1：在线执行与跨 episode 更新。**

```text
输入：任务指令，冻结 VLA、高层 Agent、VLM Observer，当前指导 Sr，执行预算
在线 episode：
```
